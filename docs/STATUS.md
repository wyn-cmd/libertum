## Where we are

- **Phase 0** (foundations, spikes): done, except the items under "Open" below.
- **Phase 1** (model, plain-text editing): done; acceptance met on the development laptop (table below).
- **Phase 2** (rich formatting and the sidebar): done. Character formatting, paragraph formatting, paragraph styles, lists, ligatures and hyphenation are bound to the selection with mixed states and exact undo, and the Layout pane's **Columns** and **Gutter** now set the caret's section (one to twelve equal columns, each at least 0.5 in wide).
- Pulled forward from later phases at the user's request: page breaks, sections with page numbers, an auto-updating table of contents, and **tables** (model, row-based pagination, cell editing, borders/fills, DOCX round-trip and the Table menu) — Phase 5/6 slices; the home screen with Blank, Manuscript and Book templates.
- **Phase 3 (DOCX): done.** `libertum-docx` reads and writes core documents (paragraphs, runs, character and paragraph styles, lists, sections, preserved package parts), and the app opens and saves `.docx` with native dialogs, a dirty title and a Save / Don't Save / Cancel prompt on close.
- **Phase 4 (ODT): done.** `libertum-odt` reads and writes OpenDocument Text packages: paragraphs, runs and text styles, common and automatic style families, bullets and numbers, sections as master pages with page setup, columns, page numbers, headers and footers (including first and even variants and `{page}`/`{pages}` fields), tabs, borders, page breaks, and tables (spans, vertical merges, fills). The `mimetype` entry is always first and stored uncompressed, unknown package parts survive a save, and the mimetype is checked on open. The app opens and saves `.odt` and `.docx`, picks the format from the file extension, and a new document is named after the Settings default format (ODT by default).
- **Phase 7 (Markdown): done, with documented limits.** `libertum-markdown` parses GFM Markdown with comrak (tables, strikethrough, task lists, autolinks, footnotes, YAML front matter) into the model, records each top-level block's original source slice and re-emits untouched blocks byte for byte; an unedited open→save is byte-identical for all eight fixtures. Edited blocks follow the file's detected conventions (emphasis, bullet, ordered delimiter, fence, ATX/Setext). `.md` opens and saves from the app; a Markdown document opens in a fixed reading geometry with no page gaps or shadows (a continuous reading column); the Format and Document panes are Markdown-filtered, and saving a Markdown file reports what will be lost (`loss_report`) before writing. **Limits:** pagination still happens underneath, and underline/super/colour in an *edited* block are lost (links, images, ordered-list starts and code lines are kept).
- **Phase 7b (RTF): done.** `libertum-rtf` has a byte tokeniser and a streaming reader (code pages via encoding_rs, `\uN` surrogate pairs), maps runs, paragraph formatting, styles, lists, tables, sections/page setup, headers/footers and `PAGE`/`NUMPAGES` fields, preserves unknown groups raw (preamble, per-paragraph byte offsets and per-furniture), and writes RTF 1.9.1 with font/colour/style/list tables and cached field results. `.rtf` opens and saves from the app. Pictures, shapes, notes, comments and nested tables are refused rather than dropped.
- **Phase 5 (page layout): core done.** Page size, orientation, margins, headers and footers (first/even), page-number fields and columns work; **Link to Previous** inherits headers/footers from the nearest earlier section; and each section now paginates, renders and lays out the canvas at its own paper size and margins. Mixed portrait/landscape documents display correctly. The Document pane still sets page setup for every section at once, so imported mixed sections render correctly but there is no per-section page-setup editor yet, and the LibreOffice page-count fixture comparison is still open.
- **Phase 6 (book features): done.** Tables, TOC, the Headers and Bookmarks panes, footnotes and endnotes with an Endnotes page, bookmarks with cross-references, inline images and named table styles are in, and each of them round-trips through DOCX, ODT and RTF. Table rows now split across pages unless the row is kept together, header rows repeat, and merged cells can be merged and split from the Table menu. The acceptance fixture is 343 pages with 200 footnotes, a 10-entry TOC, 20 inline images, 10 bookmarks with a text and a page cross-reference, and a banded table spanning four pages (one of its rows splits); pagination takes 798 ms and all three formats re-read every mapped feature.
- **Phase 8 (polish): done.** **Phase 9 (CI, packaging): partly done**: CI on four platforms with build artifacts, the Windows installer, and release 0.1.0 on GitHub; still open are macOS and Linux packages, the regression job and the LibreOffice check. **Phase 10 (stitching): done.** **Next:** Phase 11 (AO3 chapter export and tag suggestions), then Phase 12 (proofreading and AO3 sync, which needs a spike and a decision on authentication).
- **Pulled forward into Phase 8's territory (2026-11-11):** the **pageless view** (View > Pageless: one endless column as wide as the document's own paper, with no page gap, shadow, headers, footers or page numbers; on by default for Markdown and RTF, opt-in for DOCX and ODT), **table column widths** in the Layout pane (Narrower/Wider and Equal Columns, with the table keeping its overall width), and the four inspector buttons are now one equal width. The **native document format** (`.lbtd`) proposed in `docs/format-libertum-native.md` is now implemented: the app opens and saves it, and the crash-recovery snapshot uses it.

### What works in the app today

- Home screen with templates; editing with caret, selection (mouse, keyboard, double and triple click), clipboard as plain text, undo/redo. **Open** reads `.odt`, `.docx`, `.md` and `.rtf`; **Save** writes the format of the current file, Save As offers all four, and a new document uses the Settings default format.
- **Format inspector, Style pane:** paragraph style popup (Body, Title, Heading 1 to 4, Quote) and **Update** (folds the selection's own formatting into its style); then, in order, **Font** (family — every installed font — weight, size, B/I/U/S, the gear with baseline and character spacing), **Alignment** (alignment and indent buttons), **Character Colour** (text colour and highlight swatches), **Bullets & Lists** (Bullet, Numbered, Lettered, Harvard; nine levels) and **Spacing** (line spacing: Lines, At Least, Exactly, Between; space before and after). The highlight colour of the whole UI is coral orange (`theme.rs`), in both themes.
- **Layout pane:** **Columns** and **Gutter** (section settings, applied to the caret's section and read back from it; text flows down one column then the next, page and section breaks still start a page, and keep/widow rules work per column), first-line, left and right indents, **Borders & Rules** (None, Thin, Medium or Thick, black, all four sides, one undo step), and **Tabs** (Tab in the text advances to the next default stop every 0.5 in; the model also holds explicit left/centre/right/decimal stops, which the format importers will use).
- Pressing Tab outside a list inserts a tab character; inside a list it still changes the item's level.
- **Tables:** the toolbar Table button and Insert > Table add a 3×3 table as wide as the text column. Cells are edited in place; Tab/Shift+Tab move between cells (Tab in the last cell adds a row), Enter splits a paragraph inside a cell, and text and formatting commands work in a cell. The Table toolbar button opens a menu with Insert Row Above/Below, Insert Column Left/Right, Delete Row/Column/Table, **Merge with Cell to the Right**, **Merge with Cell Below**, **Split Cell** and the named **table styles** (Plain, Grid, Header Row, Banded Rows, …), all with read-back and exact undo. Rows split across pages unless the row is kept together (DOCX `cantSplit`), header rows repeat when a table continues, and cell fills, style bands and grid borders are drawn under the text. The Layout pane's **Table** group shows the caret column's width with **Narrower**, **Wider** and **Equal Columns** buttons (the table keeps its overall width). DOCX, ODT and RTF tables with grid spans, shading, vertical merges and styles open and save as tables.
- **More pane:** keep lines together, keep with next, page break before, widow and orphan control, remove hyphenation, ligatures.
- **Document tab:** page size, orientation, the four margins, Hyphenation and Ligatures are bound to the document and read back from it (undo/redo included). **Header & Footer** has working switches, distances and text: a header and footer for every page, plus their own text for the section's **first page** and **even pages**; `{page}` and `{pages}` are filled in per page (for example a running head or "Page 4 of 120"). Header and footer text is edited in the pane and follows the document's default font; it is one paragraph per variant (first/even variants are used only when their box is ticked). The **Section pane** is bound to the caret's section for headers and links; its **Page Numbering** group is whole-document: show/hide numbers, the page they start on (**Use Current Page** takes the caret's page, **Update** applies the fields), the first number (0 allowed), hide on page 1, position (top/bottom × left/centre/right) and **Alternate sides (book)** for mirrored facing-page numbers.
- **Date & Time** (Insert > Date & Time…): a fixed field (the moment of insertion) or an **Updated on save** field, in eleven formats grouped as date & time, date and time (each row previews the current clock). Updated fields are rewritten before each save; the save time and the fields round-trip through `.lbtd` (DOCX, ODT, RTF and Markdown keep the visible text only).
- **Zoom:** the toolbar has an exact percent stepper (type 1 to 800, or step by 1%); the Zoom menu has Zoom In/Out (10%), Actual Size, presets and Fit Width/Page; Ctrl/Cmd + wheel zooms around the pointer (Windows trackpad pinch). The toolbar order is View, Full Screen, Zoom, Insert, Table, Image, Footnote, then the Format and Document toggles (Page Break is in the Insert menu and on Ctrl/Cmd+Enter; the Text Box and Comment placeholders were removed on 2026-11-12); the Insert menu offers page break, section break, table, image, footnote, endnote, table of contents and page number (Bookmark was removed at the user's request).
- **Booklet view** (View > Booklet View): page 1 alone on the right, then pages 2-3, 4-5... paired left to right.
- **Find & Replace** (Cmd/Ctrl+F, or View > Find…; updated 2026-11-12: the bar opens focused, searches as the query is typed, highlights the current match in amber, shows "3 of 17", and scrolls the match clear of the bar and the word-count pill): a bar under the toolbar with the query, **Aa** (match case) and **Ab** (whole words), Prev/Next, a replace field, Replace, All and a close button. Enter and Next select the next match (wrapping); Replace keeps the replaced text's formatting; All replaces every match in one undo step. F3/Shift+F3 and Cmd/Ctrl+G also work, and Escape closes the bar.
- **Autosave and crash recovery:** while the document is dirty it is snapshotted every `autosave_secs` (default 60; 0 turns it off) into the platform data directory as a native `.lbtd`, one snapshot per window. Nothing is ever written over the user's file. After a crash the next launch (from the Start menu or by opening a file) offers **Restore** or **Discard** for the crashed window's snapshot, never for one that is still running; a save or a clean close removes the window's snapshot.
- **Home screen:** the templates plus a **Recent** list (eight files, newest first, with the folder underneath). Choosing one opens it, after the unsaved-changes prompt when needed.
- **Settings** (Cmd/Ctrl+, or View > Settings…): appearance (System, Light, Dark), the default format for new documents (ODT, DOCX, RTF, Markdown, Libertum), the autosave period, measurement units (Automatic, cm, in), graphics acceleration (which takes effect on the next start) and **Show performance overlay** (fps and frame time in the top-right of the document view, off by default). Every change applies at once and is saved to settings.toml.
- **Drag and drop:** a document dropped on the window opens; other files are ignored; a dirty document asks first.
- **Right-click context menus:** over text (Cut, Copy, Paste, Select All, Bold, Italic, Underline, Find…), over a table cell (insert/delete row and column, merge right/below, split, delete table) and over an image (Larger, Smaller, Remove). Commands are disabled when they do not apply, and every one also has a menu, pane or key route. Any other action, Escape or a click elsewhere closes the menu.
- **Native documents (`.lbtd`):** Open and Save As offer Libertum documents, which keep the whole model plus the view state (pageless and zoom). They can be the default format in Settings. Files are deterministic (the same document saves to the same bytes), images are stored once per distinct image, and anything a newer build wrote is kept byte for byte.
- **Pageless view** (View > Pageless): the document as one endless column, as wide as its own paper, with no page gap, page shadow, page numbers, headers or footers. Markdown and RTF open that way; DOCX and ODT open as pages and can be switched with the View menu item (the choice is per open document, not written into the file).
- Shortcuts (Cmd on macOS, Ctrl elsewhere; `shortcuts.rs`): B, I, U; Shift+= superscript, = subscript; L/E/R/J alignment (macOS: Cmd+{ | }); Return page break; Alt+I sidebar; Tab and Shift+Tab change list levels.
- Pagination honours page breaks, sections, keep options and widow control; whole-document page numbers (with a settable start page and first number); per-section headers and footers in the margin (first and even variants, `{page}`/`{pages}` fields, taller ones push the body); TOC with dot leaders; hyphenation (English) with drawn hyphens.

## Open items

- [ ] **DOCX import/export limits.** Inline pictures, REF/PAGEREF cross-references, table styles and row `cantSplit` now round-trip; floating, cropped, rotated or linked pictures, other fields, tracked changes and comments are refused with an error rather than dropped (tables and notes round-trip; note bodies are plain text and rich note formatting is flattened with a warning); headers and footers are not modelled (their parts and section references are preserved, but the app shows none); page-number *positions* are not imported; custom list formats and numbering restarts collapse to the nearest built-in; a soft line break becomes a space. **Export limits:** styles are regenerated from the model (character styles become direct formatting on import) and all columns are equal width, the origin's own table styles are not kept, and a table style with more than one header row renders differently in Word (its `firstRow` covers row 0 only).
- [ ] **ODT import/export limits.** Comments, tracked changes, text sections, tables of contents/indices and drawings are refused with an error rather than dropped. The exception is a picture in a `draw:frame` anchored as a character, which becomes an inline image (floating, text-box, linked, vector and header/footer pictures are still refused; a rotation is dropped with a warning). `text:bookmark-ref` with format `text` or `page` becomes a cross-reference; other formats (chapter, direction, number) keep their cached text as plain text with a warning. A table style is written as `table:template-name` plus the resolved fill on every cell; reading a built-in name restores `Table.style` and clears cell fills equal to the style fill, so a user fill identical to its row's style fill comes back as no fill (it draws the same). An unknown template name leaves the fills on the cells. Automatic paragraph styles become direct formatting, character styles become direct formatting on runs, and custom list formats/start values collapse to the nearest built-in. Sections are master pages and start only at a paragraph, so a section that starts with a table is attached to the next paragraph; page-number mirroring, ligature settings and header text longer than one paragraph are not represented (multi-paragraph header text is joined and a warning is recorded); header/footer distances are written as the header/footer style's margins, a close but not identical ODF concept; a table's outer and inner border collapse to one line (the model has one width and colour). Opening parses on the UI thread and command-line opening of a path is not wired.
- [ ] **Markdown limits.** Pagination still runs underneath the continuous reading view (page gaps and shadows are removed rather than pagination being skipped). The inspector is now Markdown-filtered (Format and Document panes offer only what a Markdown file can store) and the app shows the "formatting will be lost" prompt (`loss_report`) before a Markdown save. Images load from beside the file and are written back (unnamed ones saved as `<stem>-image-<n>.<ext>` via `to_bytes_for`/`save_with_report`), and an edited block keeps an ordered list's start number, hyperlinks (address and title), code block fences, info strings and lines, quote depth, table column alignment, and bold or italic code spans. Still lost in an *edited* block: underline, superscript/subscript and colour (the text remains), an image's title, a link around an image, and links added in the app (the model has no hyperlink). A code block is shown as one paragraph and a heading level 4 to 6 with the Heading 3 style (display only; the real level is saved); raw HTML and front matter are shown as text. Clean (unedited) blocks always save byte-for-byte.
- [ ] **RTF limits.** Pictures, shapes/objects, comments and nested tables are refused rather than dropped; notes round-trip as plain text (formatting inside a note is flattened with a warning, and endnotes use Word's `\footnote\ftnalt` form); a body `TOC`, `REF` or other non-page field is refused; `LineSpacing::Leading` comes back as `Exactly`; lengths/sizes/weights are quantised to twips/half-points/bold; paragraph borders, ligatures and separately drawn page numbers are not represented; header text is still one plain-text paragraph, so multiple RTF header paragraphs are joined with a warning; font/colour/style index references inside preserved raw snippets are not remapped when the regenerated tables differ.
- [ ] **LibreOffice is not installed on the development machine**, so exported ODT/DOCX/RTF were validated with Microsoft Word (no repair prompt) and, for ODT, odfpy rather than the LibreOffice reference. The headless LibreOffice conversion job in CI remains to be added (Phase 9).
- [ ] **IME (Korean and Mandarin) parked by the user.** The canvas re-requests the input method on every redraw; the user's 2026-11-10 note is that their earlier test still showed no composition, and they asked to leave it alone for now. Not looked at since.
- [ ] **Table limits:** a row splits across pages only when its content can be broken between lines (a tall single-line cell stays whole); merged cells can be merged and split from the Table menu, but a cross-cell selection is refused and Ctrl/Cmd+A selects the current cell; tables do not nest; there is no per-cell-border or custom table-style UI (one uniform border per table, one fill per cell, and the built-in style fills); column widths are edited one column at a time from the Layout pane, with no drag handles on the page.
- [ ] **The pageless choice is per open document and not saved.** DOCX and ODT have nowhere to store it, so reopening starts paged again (Markdown and RTF start pageless); `docs/format-libertum-native.md` proposes a `view.json` that would keep it. In pageless view a table of contents still shows real page numbers, and page breaks still start a new page (they simply have no seam to show).
- [ ] **Native-format limits:** the manifest's `features` list is written but not enforced on save (unknown `extensions/` entries are kept, which is the important half); `serde(default)` covers most structs, but the ones without a `Default` (Table, Note, Run, Paragraph, Bookmark, ListItem, ResolvedChar, ParagraphStyle, InlineImage, CrossRef) need a manifest version bump if a field is ever removed; there is no fixture in `tests/fixtures/` yet for `.lbtd` beyond the crate's own tests; ODT remains the built-in default format (the document recommends keeping the choice with the user).
- [ ] **Phase 8 limits:** the Find bar's fields take focus on click (Iced 0.14 has no public programmatic focus), so Cmd/Ctrl+F opens the bar and seeds it from the selection rather than putting the caret in the field; a table cell's context menu targets the caret paragraph's first image when images are involved; the autosave snapshot lives in the data directory and is not encrypted; the home screen's Recent list is pointer-only; menu commands still have no Alt-key access (see `docs/accessibility.md`).
- [ ] **The Document pane's page setup is still document-wide.** It writes paper, orientation and margins to every section. Imported mixed sections render correctly at their own sizes, but there is no per-section page-setup editor yet. The canvas centres pages of different widths in one readable column; booklet view sizes every slot from the largest page. Pages not paginated yet are estimated at section 0's size, so the scroll extent can adjust while a mixed document finishes laying out.
- [ ] **Headers and footers are edited in the Document pane, not on the page.** Clicking the header area of a page still places the caret on the nearest body line. Header text is one plain-text paragraph per variant in the document's default font; the model carries an alignment (left by default) but the pane does not expose it yet, and rich header formatting, multiple header paragraphs and in-page editing are not built. `{page}` and `{pages}` are the only fields; any other braces are plain text.
- [ ] **Page numbers drawn in the top margin keep their position relative to the section's page setup**, so they can overlap header text when both are switched on at the top; a header taller than the margin now only pushes its own section's body.
- [ ] **Page numbering is whole-document** (section restarts are no longer honoured for the visible count), while **header text fields still edit the caret's section**; the Header/Footer distances are document-wide like page setup. The start *page* has no DOCX/ODT/RTF equivalent, so those formats keep the visible text and position but not where counting begins.
- [ ] **Booklet view** is session state, not a saved setting; page 1 alone on the right, then pairs. Native macOS trackpad pinch is not delivered by iced 0.14 (it drops winit's `PinchGesture`); Ctrl/Cmd + wheel and the zoom stepper are the supported routes there.
- [ ] **Borders** use one colour (black) and one box per paragraph from the inspector. The model carries four independent sides and a colour for DOCX/ODT, and Word merges identical adjacent borders into one box; neither is exposed or merged yet.
- [ ] **Tabs:** a stop past the right margin is ignored instead of moving the tab's text to the next line (Word); right/centre/decimal tabs fall back to a left stop when their text wrapped to another line; a trailing tab adds invisible trailing advance. Custom stops are in the model but have no ruler/editor; DOCX `w:tab` and ODT `text:tab` mapping come with the importers.
- [ ] **`rust-version`:** the workspace says 1.85; iced, wgpu and parley need 1.88, and `rfd` 0.18 declares 1.92. The development toolchain is 1.99, so it builds; raising the declaration turns on new clippy lints, so it is the user's decision.
- [ ] Known approximations (logged in decisions.md): "At least" and "Between" line spacing use an estimated 1.2 em single line; a hyphenated line reserves 0.35 em for its hyphen, and only hyphenated lines do (a line whose fragment fills the width cannot shrink, so its hyphen may sit at the margin or overhang by less than that); hyphenation is English only (the model has no language attribute yet); font names in the font popup are drawn in the UI font, not their own.
- [ ] Colours outside the eight swatches show as "Mixed"; there is no colour picker.
- [ ] vello is not wired into the canvas; GPU crash flag (PLAN §4.5). Watermarks are drawn by the CPU page renderer only (the vello path does not draw them) and are kept only in `.lbtd` files: DOCX, ODT, RTF and Markdown do not store them yet.
