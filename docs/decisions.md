# Decisions log

Deviations from PLAN.md, newest first. One entry per decision: date, what changed, why.

- 2026-11-12: **Full screen, page thumbnails, watermarks, opening from Explorer, a Windows installer, and the CI fix.** (a) **Full screen** uses Iced's `window::set_mode` (`Fullscreen`/`Windowed`); the toolbar's second button is now Full Screen (Page Break stays in the Insert menu and on Ctrl/Cmd+Enter), F11 (Ctrl+Cmd+F on macOS) and View toggle it, and Escape leaves it only when nothing else (menu, Find, Settings, prompt) is open, without counting towards the three Escapes that go home. (b) **Text Box and Comment** were placeholders with no model behind them; they are removed rather than half-built (the model has no text frames or comments, and DOCX/ODT/RTF refuse them on import). (c) **Page thumbnails** are rendered on the UI thread by a second `PageRenderer` in `DocView`, 112 logical px wide at the display scale, only for the rows in view (one either side), keyed by the page content hash so an edit redraws just its page; at most 200 are kept. The column is virtualised (spacers above and below the visible rows), so a 1,000-page book costs the same as a short one. (d) **Watermarks** are `Section::watermark` (text and diagonal/horizontal), set on every section at once as one undo step. Layout sizes the text to 62% of the page diagonal (or 80% of the width), clamped to 18 to 220 pt, and the CPU renderer rasterises it once (at no more than 2 px per point) into a translucent grey bitmap that every strip of every page reuses, drawn turned about the page centre under all other content. It is saved in `.lbtd` (serde); DOCX, ODT and RTF watermarks are VML/draw shapes in headers and are not mapped yet, and vello does not draw it. (e) **A double-clicked file** reached `libertum.exe "<path>"`, but `main` ignored the argument; it is now passed to `App::boot`, which opens it through the normal open path. The crash-recovery offer is no longer shown in place of an open error. (f) **Installer:** `crates/libertum-installer` (no dependencies) is a windowed program that carries `libertum.exe`, `install.ps1` and the README appended to its own `.exe` (a checked trailer, plain file names only). Double-clicked, it asks, extracts to a temporary folder, runs `install.ps1` with no console window, and offers to open Libertum; `pack` builds it. Reusing the tested script keeps one install route. No installer toolkit (Inno Setup, NSIS, WiX) was available, and none is needed. Unsigned, like the program. (g) **CI:** every run since the repository was published failed on Windows: `backend_trait_works_for_both` opened `HeadlessGpu::new()` (any adapter) instead of `for_tests()` (hardware only), so on the runner it rendered on WARP and vello crashed the test process (STATUS_ACCESS_VIOLATION). It now skips software adapters like the other GPU tests. CI also builds the installer on Windows and uploads each platform's release build as an artifact, and waits for the windowed installer with `Start-Process -Wait` (PowerShell does not wait for GUI-subsystem programs otherwise).
- 2026-11-12: **Faster Find, sounder stitching, a calibrated wheel, and a paginator that gives way.** (a) **Find:** `Editor` keeps the full match list for the query searched last, keyed by the query, its options and a new `Document::revision()` counter (bumped by every applied operation, undo and redo included; it is bookkeeping, so it never makes two documents unequal and is not saved). Next, Previous and the "3 of 17" count are now a binary search in that list instead of a pass over the text. The scan itself reuses its buffers, lowercases ASCII runs in place and only builds an offset map for text whose lowercase form changes length. A query that extends the previous one rescans only the paragraphs that matched (not for whole-word searches). On the 1,000-page demo (576,144 words): a fresh query 52 ms -> 20 ms, each step 52 ms -> 0.0004 ms (`cargo run --release -p libertum-editor --example find_bench`). (b) **Stitching:** paragraph styles are now remapped by name into the book's style sheet (a source whose sheet was in another order showed its text in the wrong styles); the book keeps one table of contents, the first found, rebuilt from every chapter, and later sources' own contents lists are left out; clashing bookmark names are renamed with the source's cross-references following; the section list always matches the section starts; and the document is built once at the end instead of being re-indexed per source and per contents entry. A file that fails to open returns to the stitch list with the files that did open. (c) **Scrolling:** the mouse wheel used to jump 80 px and then coast about 164 px more on a velocity that each event overwrote, so one notch moved roughly 244 px and a trackpad's own inertia was doubled. A notch (a whole number of lines) is now 100 logical px, added to a pending distance the view glides to (each frame covers `1 - exp(-20 dt)` of what is left), so the total is exact, notches add up and a notch the other way cancels the rest. A trackpad's fine deltas are applied as they come. (d) **The background paginator starved everyone else:** it released the layout lock and took it straight back (the system lock is not fair), so the UI thread waited for the whole document to paginate before it could read anything: 1.07 s to show a stitched 450-page book, and the same on any long document while it paginates. `SharedLayout` counts waiting threads and the paginator starts its next chunk (now 4 pages, about 12 ms) only when nobody is waiting: 1.07 s -> 46 ms.

- 2026-11-12: **Phase 10 stitching, going home, caret size, inertial scrolling, and an unsigned installer.** (a) **Stitching** (`crates/libertum-app/src/stitch.rs` + `Document::restamp`/`append_blocks`/`next_free_id`/`max_list_group` in the model): the first document supplies styles and defaults; every later one follows as a new section. (c) **Caret size:** the caret now uses the line's content box (`content_block_min/max_coord`) instead of its line box, so it matches the text rather than the leading between lines. (d) **Inertial scrolling:** the wheel leaves velocity behind (about 960 px/s for a notch), the page coasts on a frame subscription and decays to 2% per second, stopping below 20 px/s or at the edges. (e) **Installer:** `packaging/windows/install.ps1` installs per user without administrator rights or an installer framework (program under `%LOCALAPPDATA%`, Start Menu and desktop shortcuts, ProgIDs and `OpenWithProgids` for `.lbtd`, `.odt`, `.docx`, `.rtf` and `.md`, plus a `RegisteredApplications` entry so Libertum appears in Default apps), and writes its own uninstaller. **Signing is out of scope** (no certificate authority will issue one), so installers are unsigned and documented as such. - 2026-11-12: **GPU tests skip software rasterisers.** The Windows CI runner exposes a software adapter (WARP), and rendering a page with vello on it took the test process down with an access violation inside `tests/gpu_smoke.rs`; a crash like that cannot be caught by an assertion, so the job failed instead of reporting anything useful. `HeadlessGpu` now reports `is_software_adapter()` (device type `Cpu`, or a name containing WARP, llvmpipe, SwiftShader, Basic Render Driver or software) and the tests go through `for_tests()` / `for_tests_iced_like()`, which return `None` for such an adapter. The CPU/GPU parity comparison therefore runs on real hardware (verified here: 9 render tests and the 3 smoke tests pass on the AMD iGPU) and skips on a runner that cannot render. This is a behaviour statement, not just a CI workaround: a software adapter is refused rather than trusted to produce pixels.

- 2026-11-11: **Native document format proposed (`.lbtd`), not adopted.** `docs/format-libertum-native.md` specifies a ZIP container (`mimetype` first and stored, `manifest.json`, `document.json`, optional `view.json`, `media/<hash>.<ext>`, opaque `extensions/`) that stores the model one-to-one as JSON. It exists because the interchange formats cannot hold pageless state, model ids and versions, image hashes or unknown-key preservation, and because the DOCX and ODT writers regenerate parts (styles, font tables) they do not model. Determinism (fixed entry order, sorted keys, zeroed timestamps) is part of the spec so fixtures can be hash-compared; `#[serde(default)]` plus the `extensions/` map carry forward compatibility; `serde`/`serde_json` are MIT/Apache-2.0, so rule 4 holds. Estimated at about ten days across six steps (serde on the model, a `libertum-native` crate, fixtures and a proptest, app wiring, `view.json`, docs). **No code was written:** the proposal recommends landing it after Phase 8, with the current ODT default kept behind the existing Settings choice. The document records the alternatives (an ODT profile, CBOR, SQLite) and the risks (a fourth format doubling the round-trip matrix, schema churn, size versus ODT).

- 2026-11-11: **DOCX inline images, cross-references, table styles and `cantSplit` (`libertum-docx`).** Images are written as `w:drawing/wp:inline` (extent in EMU, 12700 per pt; `docPr` descr = alt; name in `pic:cNvPr`), one `word/media/lbt-<hash>.<ext>` part per distinct hash, with `rIdImg<n>` relationships and png/jpeg Default content types; on save from an origin package the old `lbt-` parts and `rIdImg` relationships are stripped and re-added. Reading refuses (typed error) floating `wp:anchor`, VML, non-picture, linked, cropped, rotated and undecodable pictures. Cross-references are `REF name \h` and `PAGEREF name \h` fields, read from both `fldSimple` and complex fields; only the `\h` and `\*` switches are accepted, and every other field (PAGE, NUMPAGES and so on) is still refused. A text-REF target bookmark is written spanning to the paragraph end, and hidden `_Ref` bookmarks are kept on read only when a field uses them. Table styles are written once per distinct `TableStyle` (id `Tbl<name>`, based on `TableNormal`): `firstRow` shading for `header_fill`, `band2Horz` for `band_fill`, plus `w:tblLook`; a cell's own `w:shd` stays its own fill. Two styles sharing a name with different fills read back as "Name 2". Word's `firstRow` covers only row 0, so styles with `header_rows > 1` render differently in Word. `w:cantSplit` maps to `TableRow.keep_together` both ways; absent means false (Word's default), which changes the previous reader behaviour of always true. `tblPr` children are now in schema order. `styles.xml` is still regenerated wholesale, so the origin's own table and character styles are lost. Checked in Word 16 via COM (opens without repair; 1 inline shape, 2 fields, style "Banded Rows"); LibreOffice not checked.

- 2026-11-11: **Markdown images, loss report and edited-block fidelity (`libertum-markdown`).** New dependency: `libertum-formats-common` (workspace crate, for `media_from_bytes`); no external crates added. **Images:** `Markdown::open(path)` (and `Markdown::parse_with_base_dir`) loads an inline `![alt](target)` whose target is a local file (relative to the document, or absolute; a percent-encoded name is tried too) that exists, is at most 32 MiB and decodes (PNG/JPEG as they are, GIF/BMP converted to PNG). It becomes an `InlineImage` at its text offset (`alt` = the alt text with emphasis markers dropped, `name` = the target as written, fitted to 420 pt wide) and the syntax is not left in the text. A URL (any `scheme:`, `//host`), a missing, oversized or undecodable file keeps the alt text and adds a warning that names the target; the network is never used and one bad image never fails the open. `Markdown::parse` has no folder, so it loads nothing (old warning kept). An edited block writes `![alt](name)` at each image's offset (alt escaped; a name holding spaces or parentheses goes in `<...>`); the image title and displayed size are not kept. An image with an empty `name` (inserted in the app) is saved beside the document as `<document-stem>-image-<n>.<ext>` when the save has a path (`Markdown::to_bytes_for(Some(path))` returns the files as `MarkdownAsset`s; `save`/`save_with_report` write them first, then the text); the next free `n` is used, an existing file with the same bytes is reused and a different file is never overwritten. With no path it writes the alt text and returns a warning. The image `name` in the model is not updated after such a save, so the next save reuses the same file. Fingerprints hash an image through its cached hash instead of Debug-formatting its bytes. **Loss report:** `loss_report(&Document) -> Vec<Loss>` (kind enum `LossKind`, count, British-English `Display`), pure, checked against what `write.rs` emits; it counts only set formatting, ignores what the importer itself sets (paragraph spacing, quote indent, table column alignment) and is empty for every fixture. Not reported on purpose: paragraph spacing, keep/widow settings, hyphenation, section names, header distance. **Edited-block fixes done in the crate, no model change:** per-block notes kept from the import (`Hints`) restore an ordered list's start number (by list group and level), a hyperlink's address and title (the span is re-anchored by comparing the unchanged start and end of the paragraph text, so typing inside or beside a link works and deleting its text drops it; a link whose text is its address is written as `<url>`), and a code block's fence character and length, info string and line breaks (an edit is mapped onto the original lines by its unchanged start and end). The writer now also keeps quote depth (from the indent), table column alignment (`:---`, `:---:`, `---:`; the importer now reads `:---` as an explicit start alignment), a code span that is also bold or italic, spans and merged cells as empty cells so columns stay aligned, heading levels clamped to 6, the file's conventions when the whole document is re-serialised, and an edited block no longer gains a blank line it did not have. **Still open:** a block is shown with Heading 3 for levels 4 to 6 (display only; the level is kept when saved), a code block is one paragraph in the editor (the model has no code block), an image's title and a link around an image are lost in an edited block, a link added in the app cannot be written (no model hyperlink), raw HTML and front matter are text, multi-paragraph list items become separate items, a loose list is written tight, and a heading inside a list or quote is not rebuilt.

- 2026-11-11: **ODT inline images, cross-references and table styles.** Images are written as `draw:frame` (`text:anchor-type="as-char"`, `svg:width`/`svg:height`, `draw:name` when set, graphic style `LibertumPicture`) holding `draw:image xlink:href="Pictures/<hash>.<ext>"` and `svg:desc` for the alt text, at their byte offset between text nodes like notes and bookmarks; one `Pictures/` entry per distinct picture, listed in `META-INF/manifest.xml` with its media type. A picture already in an imported package is reused by byte comparison; a `Pictures/` entry that the old `content.xml` referenced and the new one does not (image deleted, or GIF now stored as PNG) is removed from the package and manifest, while entries the old content never named are kept.
